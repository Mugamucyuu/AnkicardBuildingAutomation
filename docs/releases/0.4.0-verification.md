## Original published 0.3.0 to published 0.4.0

The final cross-version run used both original public release installers, not local rebuilds. The 0.3.0 installer is 248,620,201 bytes, SHA-256 `b86e6289ab074b10b7b67b4e7fc1f2f54aa0345a7765101d45e196bc1b0d26fc`; the 0.4.0 installer matches the digest above. Large browser-download connections were truncated, so the artifacts were retrieved from GitHub's official asset interface in byte ranges and verified in full before execution.

The official 0.4.0 installer was preloaded into the isolated old application's download cache. The unmodified 0.3.0 app then performed its own live official release lookup, fetched the published checksum, validated the cached installer and accepted the install request. This checks discovery and installer verification; it does not claim an uninterrupted download through the old UI.

| Original binary check | Result |
| --- | --- |
| Launch original 0.3.0 and generate three demo cards | Passed |
| Original updater detects public stable 0.4.0 | Passed |
| Original updater checks official cached installer against live release metadata/checksum | Passed; state `ready` |
| Original updater closes app and starts installer after install request | **Failed**; state remains `install_requested`, owned host does not exit within 30 seconds, no installation handoff |
| End only the isolated stalled test host, run official 0.4.0 Setup without specifying a directory | Passed; original installation registration/directory reused |
| Retain old preferences and three saved jobs; run the upgraded native smoke check | Passed; six jobs afterward, including the three original jobs |
| Remove disposable application after testing | Passed; test state retained |

The one-click upgrade requirement is therefore **not met by an already installed original 0.3.0**. Its native close code must first be replaced, which requires this one manual Setup upgrade. Publishing 0.4.0 cannot change the old process before that process launches the installer. The 0.4.0 application's corrected native close flow and the actual installer helper/relaunch path pass their checks separately.
